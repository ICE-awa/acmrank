# ACMRank 任务拆解

## 1. 目标
- 将 ACMRank 拆成一组可以连续落地的开发任务。
- 每个任务尽量控制在单个分支、单个 PR 可以完成的范围内。
- 后续实现时，默认按本文档顺序推进；如果中途产品口径调整，先更新 `docs/`，再调整任务顺序。

## 2. 执行原则
- 所有任务都以 `docs/PRD.md`、`docs/technical-architecture.md`、`docs/platform-data-integration.md`、`docs/atcoder-extension-sync.md` 为准。
- 每个任务结束时都需要：
  - 补齐对应测试
  - 跑对应验证命令
  - 更新必要文档
  - 提交并推送当前分支
- 单个任务优先做到“可合并、可验证、可回归”，不要把多个大主题揉进同一个任务。
- 优先先打基础，再接同步链路，再接聚合与排行榜，最后补前端完整体验与上线增强。

## 3. 里程碑

### 里程碑 A：基础骨架可运行
- 目标：仓库结构、开发规范、基础服务骨架、数据库迁移、鉴权与账号体系建立。

### 里程碑 B：核心数据链路跑通
- 目标：`Codeforces / AtCoder / 洛谷 / ICPC / Clist` 的基础同步链路、题目事实和 `first_ac_at` 能闭环。

### 里程碑 C：排行榜闭环可用
- 目标：`AT / CF / SCNU` 计算、快照、昨日变化值、今日新 `AC` 数和热力图统计链路跑通。

### 里程碑 D：公开产品可用
- 目标：公开用户页、平台视图、单账号视图、排行榜页和管理端最小闭环可用。

### 里程碑 E：补齐兜底与上线质量
- 目标：`AtCoder` 用户扩展、告警、搜索增强、集成测试、回归测试、部署完善。

## 4. 任务列表

### T00 仓库初始化与工程脚手架
- 目标：建立单仓库目录骨架和最小开发入口。
- 交付物：
  - `web/`、`server/`、`sync/`、`deploy/`、`scripts/` 基础目录
  - Go 模块初始化
  - 前端 `pnpm` 工程初始化
  - Python 同步工程初始化
  - 基础 `Makefile` 或任务脚本
- 验收标准：
  - 前后端和 Python 工程都能在本地初始化依赖
  - 目录结构与架构文档一致

### T01 基础开发规范与 CI 骨架
- 目标：把日常验证链路先建立起来。
- 交付物：
  - Go 格式化、lint、测试脚本
  - 前端 `prettier / eslint / vitest / playwright` 脚本
  - Python 格式化、lint、测试脚本
  - GitHub Actions 或等价 CI 骨架
- 验收标准：
  - 空项目或最小示例代码可跑通基础检查
  - CI 能在 PR 上执行基础门禁

### T02 Docker Compose 本地基础设施
- 目标：把开发依赖服务先跑起来。
- 交付物：
  - `PostgreSQL`
  - `Redis`
  - `NATS + JetStream`
  - `ElasticSearch`
  - 必要初始化脚本
- 验收标准：
  - `docker compose up` 后基础服务可访问
  - 本地开发环境变量与连接方式明确

### T03 数据库迁移与核心表设计
- 目标：建立业务真值存储结构。
- 交付物：
  - 用户、平台账号、账号审核表
  - 平台资料快照表
  - 原始 `AC` 事件表
  - `problem_fact`
  - `contest_ac_summary`
  - 奖项历史表
  - `clist` 映射表
  - 排行榜与快照表
  - 热力图日统计表
- 验收标准：
  - 迁移可重复执行
  - `first_ac_at` 被明确建模

### T04 后端服务骨架与依赖注入
- 目标：把 `api / scheduler / aggregator` 三个 Go 进程骨架搭起来。
- 交付物：
  - 三层架构基础目录：`handler / service / repository`
  - 版本化边界目录：`dto/v1`、`handler/v1`
  - 配置加载
  - 数据库、Redis、NATS 依赖注入
  - 健康检查接口
- 验收标准：
  - 三个进程都能启动
  - 依赖注入清晰，无全局隐式单例

### T05 鉴权、会话与用户注册登录
- 目标：建立用户体系和基础鉴权能力。
- 交付物：
  - 注册
  - 登录
  - 登出
  - 会话管理
  - 邮箱验证基础流程
  - 用户资料基础接口
- 验收标准：
  - `username / email / real_name / password` 流程可闭环
  - 会话与权限控制可测

### T06 平台账号绑定与审核流
- 目标：建立多平台多账号管理能力。
- 交付物：
  - 账号新增、删除、查询
  - 审核通过、禁用、状态变更
  - 平台账号唯一归属约束
- 验收标准：
  - 单个平台账号不能绑定到多个站内用户
  - 未审核账号不会进入统计

### T07 Codeforces 主链路同步
- 目标：先打通最稳定的平台。
- 交付物：
  - 资料同步
  - `AC` 题目同步
  - 首次 `AC` 时间归并
  - 比赛历史同步
  - `maxRating` 展示字段
- 验收标准：
  - 官方 API 数据能落库
  - `problem_fact` 与 `contest_ac_summary` 能正确生成

### T08 洛谷稳定链路同步
- 目标：补齐第三个刷题平台的最小可用链路。
- 交付物：
  - 资料同步
  - 过题列表同步
  - 平台 `rating` 同步
- 验收标准：
  - 去重后的洛谷题目事实可查询
  - 不参与 `SCNU Rating`

### T09 ICPC 奖项历史同步
- 目标：先把竞赛档案中的奖项模块落地。
- 交付物：
  - 真实姓名匹配逻辑
  - 奖项记录落库
  - 人工修正入口预留
- 验收标准：
  - 用户页所需奖项字段可完整返回

### T10 AtCoder 主链路与告警骨架
- 目标：建立 `AtCoder` 主链路，不把用户扩展当主通路。
- 交付物：
  - 运营 `Cookie` 配置与加密存储
  - 主链路同步适配器
  - 主链路失败告警
  - 第三方 API 与 `Clist` 告警框架
- 验收标准：
  - `AtCoder` 主链路能同步资料、比赛、`AC` 事实
  - 关键链路失败有告警记录

### T11 Clist 映射与题目评分回填
- 目标：建立 `SCNU Rating` 的题目权重基础。
- 交付物：
  - `Codeforces / AtCoder` 题目到 `Clist` 的映射
  - `problem.rating` 回填
  - 失败重试与回填任务
- 验收标准：
  - `Clist` 不作为 `AC` 事实源
  - 已通过题可以补齐 `clist_rating`

### T12 聚合器：题目事实与 first_ac_at 闭环
- 目标：把“原始同步结果 -> 平台事实 -> 用户聚合事实”跑通。
- 交付物：
  - `accepted_event_raw` 归并
  - `problem_fact` 归并
  - `contest_ac_summary` 归并
  - 多账号平台内去重
- 验收标准：
  - 同平台多账号按题目唯一标识去重
  - `first_ac_at` 可稳定重建并查询

### T13 排行榜计算与快照
- 目标：把核心产品指标计算出来。
- 交付物：
  - `AT_Best / AT_Recent / AT_Training`
  - `CF_Best / CF_Recent / CF_Training`
  - `SCNU Rating`
  - 每日 `23:59` 快照
  - 昨日变化值计算
  - 今日新通过题数统计
- 验收标准：
  - 排行榜默认按 `SCNU Rating` 排序
  - `洛谷 / ICPC` 不参与评分

### T14 公开 API v1
- 目标：先提供前端可消费的公开接口。
- 交付物：
  - 用户公开资料接口
  - 题目列表接口
  - 奖项历史接口
  - 排行榜接口
- 验收标准：
  - 返回结构稳定
  - 支持题号和 `contestId` 搜索排序

### T15 管理端 API v1
- 目标：把审核与同步运维入口先建立起来。
- 交付物：
  - 账号审核接口
  - 同步任务查看接口
  - 配置接口
  - 手动同步入口
- 验收标准：
  - 运营能管理账号、查看链路状态、配置必要凭证

### T16 前端基础框架与路由壳
- 目标：搭建站点基础外壳。
- 交付物：
  - 路由结构
  - 公共布局
  - 登录注册页
  - 设置页基础壳
  - 管理端基础壳
- 验收标准：
  - 前端能连接到后端基础接口
  - 基础路由和鉴权流可跑通

### T17 用户公开页与题目视图
- 目标：落地主产品页面。
- 交付物：
  - 用户聚合视图
  - 平台聚合视图
  - 单账号视图
  - `ICPC` 奖项历史模块
  - 题目列表搜索与排序
- 验收标准：
  - 仅展示 `AC` 列表
  - 视图切换符合产品定义

### T18 排行榜页、折线图与热力图
- 目标：把核心可视化产品价值落地。
- 交付物：
  - 排行榜页
  - `SCNU Rating` 折线图
  - 每日新 `AC` 热力图
  - 昨日变化值与今日新通过题数展示
- 验收标准：
  - 图表口径与后端统计一致
  - 热力图只统计每日新 `AC`

### T19 AtCoder 用户扩展兜底链路
- 目标：补齐最后一层兜底，而不是替代主链路。
- 交付物：
  - 扩展绑定
  - 同步窗口初始化
  - 窗口内 `AC` 上传
  - 服务端归并
- 验收标准：
  - 扩展只上传窗口内 `AC`
  - 服务端能归并到 `first_ac_at` 和比赛 `AC` 汇总

### T20 搜索增强与 ElasticSearch 派生索引
- 目标：提升管理端和题目搜索体验。
- 交付物：
  - 题目搜索索引
  - 同步日志索引
  - 增量刷新机制
- 验收标准：
  - `ElasticSearch` 只承载派生索引，不承载事实查询

### T21 集成测试、回归测试与上线加固
- 目标：把项目从“能跑”提升到“能长期维护”。
- 交付物：
  - 后端集成测试
  - 前端 `Playwright` 关键路径测试
  - 关键同步链路回归测试
  - 告警、日志、运维文档
  - 发布前检查清单
- 验收标准：
  - 关键用户路径与关键同步链路都有自动化覆盖
  - 可以支撑后续持续迭代

## 5. 建议执行顺序
1. `T00 -> T01 -> T02 -> T03 -> T04`
2. `T05 -> T06`
3. `T07 -> T08 -> T09`
4. `T10 -> T11 -> T12 -> T13`
5. `T14 -> T15 -> T16 -> T17 -> T18`
6. `T19 -> T20 -> T21`

## 6. MVP 截止线
- 如果要先做最小可用版本，建议先完成：
  - `T00` 到 `T18`
- 这样可以得到：
  - 可注册登录
  - 可绑定审核账号
  - `Codeforces / AtCoder / 洛谷 / ICPC` 基础展示
  - `SCNU Rating` 排行榜
  - 折线图与热力图
- `T19` 到 `T21` 作为增强与上线质量阶段补齐。

## 7. 后续执行方式
- 后续每一轮实现时，从本文档中明确一个任务编号作为当前目标。
- 如果某轮任务过大，再在该任务下继续拆子任务，但不要跳过上游依赖。
- 如果用户要求调整优先级，以用户最新指令为准，但需要显式说明变更后的依赖影响。
